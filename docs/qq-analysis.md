# QQ 头像工具：交付说明与源码分析

分析与构建日期：2026-10-11。

## 交付结论

已生成 `bin/QQAvatarTool.exe`，在当前 Windows 11 主机（内核版本 10.0.26200）完成编译、窗口启动和离线验证。这是依据原易语言上传协议制作的 **C# / WinForms 移植修复版**，不是原 `.e` 工程直接编译的产物。运行无需安装易语言、Python、Node.js 或原包内的 Calculation.dll，使用 Windows 的 .NET Framework 4.x。

本仓库包含 C# 移植版源码、测试夹具和构建脚本。原易语言工程、第三方 EC 模块、DLL 和截图未随本仓库分发。分析中的原工程名称用于说明协议来源。

没有使用真实账号进行上传、扫描 QQ 内存或运行 NapCat。本版不能承诺腾讯旧接口目前仍可用，也不能承诺透明或动画头像在所有 QQ 客户端中显示一致。

| 路径 | 本版实现 | 限制与验证状态 |
| --- | --- | --- |
| 原版 QQNT 直接获取 UKey | 未实现 | 原工程的旧 DLL、32 位远程调用、窗口类名和内存特征不能直接沿用 |
| 已配置 NapCat 的 QQNT | 本地 HTTP 桥接普通头像设置 | 已按当前源码接口实现并通过模拟服务测试；真实 QQNT 未实测 |
| 普通、透明、半透明头像 | 图片准备与旧上传协议已实现 | 透明度处理本地已验证，服务端是否保留透明通道需实测 |
| 旧动态头像 | 保留原 GIF 上传 | 各客户端是否显示动画需实测 |

## 使用方法

### 先验证本地图片功能

1. 双击 `bin/QQAvatarTool.exe`。
2. 选择 PNG、JPG 或 GIF；图片最大 3 MiB，尺寸最大 4096×4096，GIF 最大 300 帧且有总像素限制。
3. 静态图片可调不透明度，点击“导出 PNG / 原图”。也可以“生成全透明”后导出 PNG。
4. GIF 点击“GIF → APNG 导出”可保存动态 PNG，不需要 QQ 或任何票据。

动画预览显示首帧。GIF/APNG 不透明度须保持 100%，避免半透明操作丢失动画；动画本身已有的透明区域会保留。GIF 的有效帧时长保留，零时长帧按 100 ms 处理，循环设为无限，与原工具的循环设置相同。

### 使用旧上传协议

1. 输入自己的 QQ 号。群功能另填群号。
2. 粘贴原工具使用的 UKey：104 字节，也就是 208 个十六进制字符。允许空白分隔。网页 skey、p_skey、Cookie、NapCat Token 不能代替它。
3. 也可以点击“刷新”，选择怀旧版 QQ.exe，然后“读取旧 QQ UKey”。读取器只接受带 KernelUtil.dll 的旧 32 位 QQ。账号需要手动输入，程序不会注入 QQ 获取账号，也无法离线判定多个候选票据中哪一个有效。
4. 如有原工具生成的 `头像key.ini`，先输入对应 QQ 号，再点击“导入旧 INI 票据”。文件仅被读取，不更新。
5. 选择上传类型并点击上传。大小限制在图片转换完成后检查：普通头像 3 MiB，其余旧类型 2 MiB。
6. 在 QQ 中刷新并核对结果。程序收到原 field 7 标记时会明确说明这是协议标记；不会把接收到响应等同于已确认客户端显示效果。

默认服务器保留原工程的 `120.232.130.72`，可在界面修改为域名或 IPv4。当前没有证明该地址仍可用于所有类型。旧协议使用明文 TCP/HTTP；type=90 的 443 端口同样是原始 TCP，并非 TLS。

读取旧 QQ 时如遇权限不足，可以关闭工具后右键选择“以管理员身份运行”。普通图片处理、手动票据上传和本地 QQNT 桥接无需主动提权。程序启动不扫描 QQ、不连接服务器、不更换头像，也不保存 UKey 或桥接 Token。

### 使用 QQNT 本地桥接

前提：你已自行配置并登录 [NapCat](https://github.com/NapNeko/NapCatQQ)，并开启 OneBot HTTP 服务。这个 exe 不会安装 NapCat，也不会修改 QQ 安装文件。

1. 点击“QQNT 桥接设置”，填 `http://127.0.0.1:实际端口/` 和服务的 Access Token。例如 `http://127.0.0.1:3000/` 只是默认示例，并不意味着你已开启这个端口。
2. 输入 NapCat 当前登录的 QQ 号，选择图片。
3. 上传类型选择“QQNT 普通头像（本地 NapCat）”，此模式不需要 UKey，忽略旧服务器地址。
4. 上传前程序调用 `get_login_info` 核对 QQ 号；一致才调用 `set_qq_avatar`，通过本机临时图片文件传送原图或处理后的 PNG。
5. 成功需要桥接返回 `status=ok` 且 `retcode=0`。最终透明与动画显示效果请在 QQ 中核对。

仅允许 IPv4 回环 `127.0.0.1`，不跟随重定向、不使用系统代理。失败消息不展示含图片数据、票据或 Token 的原始请求/响应。桥接不能直接连接未配置 NapCat 的原版 QQNT。

## 原工程分析

### 为什么不能简单替换 QQNT 的 exe 名称

`窗口程序集_启动窗口.txt` 的 `pid取uin` 调用旧 `KernelUtil.dll` 导出符号 `?GetSelfUin@Contact@Util@@YAKXZ`，并构造 32 位汇编在 QQ 进程中执行。另一个账号枚举方法依赖旧窗口类名 `5B3838F5-0C81-46D9-A4C0-6EA28CA3E942`。票据读取搜索 `88 01 01 92 01 68`，按固定偏移取 104 字节。

这些都是旧客户端实现细节。QQNT 适配需要重新建立认证与上传接口的对应关系，无法只改客户端名称、地址或进程位数。没有对 QQNT 执行试探性远程调用。

### 上传协议保留情况

| 类型 | 原工程协议值 | 连接 |
| --- | --- | --- |
| 普通头像 / 旧 GIF 动态头像 | `PicUp.DataUp`，baseHead field 8 = 5 | 原始 TCP，80 |
| 小世界头像 | field 8 = 90，额外字段 3 为 `00 05 00 00` | 原始 TCP，443 |
| 名片背景 | field 8 = 21 | 原始 TCP，80 |
| 群头像 / 封面 | `httpconn`，`htcmd=0x6ff0607` | HTTP，80 |

帧格式为 `0x28 + 4 字节大端 protobuf 长度 + 4 字节大端图片长度 + protobuf + 原始图片 + 0x29`。104 字节 UKey 写入 segment field 6，图片 MD5 写入 field 8 和 9。对大小、命令、票据和 MD5 的独立解析验证均通过。

### 已在移植版改进的问题

- 原工程刚启动便显示“连接服务器成功”，当时并无连接检查；本版显示尚未连接。
- 原工程上传前未实际执行提示中的 2/3 MiB 限制；本版在图片处理之后强制检查。
- 原工程单次收取网络响应可能遇到 TCP 分片；本版按帧长度完整读取，限制响应大小并验证首尾标记。
- 原工程 field 7 非空便显示“上传成功”，群接口只检查响应头群号；本版分别报告协议标记和 HTTP 结果，提示客户端复核。
- 原工程自动把票据明文写入运行目录的 INI；本版没有持久化票据功能，支持显式只读导入。
- 原工程通过窗口标题中的文字判断是否有管理员权限，提示后仍继续；本版直接处理 Windows 读进程权限失败。
- 原工程 `pid取uin` 在申请内存成功但获取导出地址失败时提前返回，会漏掉释放；本版不用远程汇编、远程内存申请或进程写入。
- 原工程处理 GIF 时直接在图片数据中搜索固定字节模式取时长；本版使用 GDI+ 的 GIF 帧时长属性并生成具有 CRC 的 APNG chunk。
- 原工程把转换后的 APNG 覆盖选中的 GIF；本版保留原图，按上传或导出用途生成独立数据。
- 原工程依赖作者电脑的 `G:\新建文件夹\...ec` 绝对模块路径；新程序不依赖这些路径或第三方 DLL。

## 编译与验证

### 新程序

在 PowerShell 中运行 `src/build.ps1`。它只使用 Windows .NET Framework 的 `csc.exe` 与系统程序集，不联网下载依赖。编译结果写到 source 的上一级目录。

当前完成：

- exe 编译成功。
- 主窗口创建、布局渲染、六种模式和默认选择验证通过。
- 38 项 C# 离线断言通过，包括半透明像素、票据格式、protobuf、帧分片、错误长度、群号转换和本地 TCP 响应。
- QQNT 模拟 HTTP 服务：登录信息核对、Bearer Token、临时图片文件传输、成功返回解析通过；登录账号不一致时没有发送更换头像请求。
- Pillow 独立解码两个 GIF 转 APNG 的结果，共 7 帧，核对有效像素、透明区域与各帧时长，包括 partial-frame GIF 的不同 disposal 设置；所有 PNG chunk 的 CRC 通过。
- 独立 Python protobuf 解析器核对普通头像请求的协议字段、票据、MD5 与大端帧长度通过。

日志见 `验证记录-v1.0.1.txt`。模拟接口与账号均为测试值，测试没有调用 QQ、读取实际票据或连接腾讯上传接口。窗口图像使用 WinForms DrawToBitmap，部分原生组合框文字在该渲染方法中未绘出，但默认选择通过程序状态检查；它不是整桌面截图。

未完成真实测试：旧 QQ 内存读取、腾讯服务端上传、真实 NapCat 与 QQNT 上传、手机/电脑头像刷新与动画播放。

本机没有易语言 IDE/编译器与支持库。`e-packager compile-check` 返回 `compile_check_eide_not_found`。所以没有交付“原工程已编译”的声明或虚假的原生编译件。
