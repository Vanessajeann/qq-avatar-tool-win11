# v1.0.1：QQNT 桥接大响应修复

日期：2026-10-11。

请关闭旧头像工具，运行 `bin/QQAvatarTool.exe`。NapCat 保持运行并登录。

点击“QQNT 桥接设置”，填 `http://127.0.0.1:3000/` 与 HTTP 服务器配置中的 Token，再点击“应用到本次运行”。新版会自动切换到 QQNT 普通头像模式，无需 UKey。输入自己的 QQ 号，重新选择图片后上传。

## 修复内容

旧版把图片以 Base64 发给 NapCat，但只允许读取 1 MiB 响应。NapCat 的 `SetQQAvatar` 源码中，若设置头像失败，错误消息可能包含整个 `payload.file`；当它是 Base64 图片时，返回的 `message` 与 `wording` 都可能很大，导致旧工具只显示“本地桥接响应过大”。这是已复现的触发路径，尚未确认它就是用户本次失败的全部原因。

新版通过本机临时图片文件传送 PNG/JPG/GIF，保留对应扩展名；接口请求不再包含整张图片的 Base64。登录 QQ 号核对成功后才创建文件。成功或失败响应结束后清理临时文件。

响应上限调整为 16 MiB，用来接收并解析较大的接口错误；界面只显示至多 400 字符的脱敏原因。不会因为响应变大就把接口失败当成成功。

失败信息现在包含接口名称和 retcode，并区分 Token 验证失败、管理网页地址、连接失败与超时。超时会提示先核对 QQ 头像，避免重复上传。

## 验证

38 项离线测试通过，覆盖正常头像请求、临时文件中的原始图片字节、成功/失败后文件清理、账号不一致时阻止上传、2 MiB 以上的 Base64 失败响应解析、错误原因保留、图片与 Token 脱敏、管理网页识别及 HTTP 403 提示。主窗口启动测试通过。

本机 `http://127.0.0.1:3000/get_login_info` 在未带 Token 的只读请求中返回 HTTP 403，说明此端口有响应且要求认证。未读取你的 Token，未实际更换头像。

如果新版仍报错，请把提示文字或截图发来；无需提供 Token。新版错误原因可以帮助判断图片格式、QQ 状态或接口兼容性问题。

本次修复不改变功能范围：QQNT 桥接用于普通头像设置，透明与动画效果仍需在 QQ 中确认，小世界动态图层未通过这条接口实现。
